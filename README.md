# FlowCraft AI

**そのExcel作業、自動化する前に、見直そう**

Excel・CSVを使う定型業務について、**作業そのものの見直し（AI業務改善診断）**から、**処理の組み立て・実行**、**結果が業務として正しいかの確認**、**次回の再実行**までを支援するWebアプリケーションです。

不要な作業をそのまま自動化しないこと、AIの提案や処理の結果を人が確かめてから使うことを、設計の中心に置いています（考え方：[docs/product-review.md](docs/product-review.md)）。

> **PC専用**：Windows の Chrome・Edge（マウス・キーボード操作）向けです。確認解像度は 1920×1080 と 1366×768。スマートフォンから開くと「PC専用です」の案内だけを表示します（[docs/pc-only.md](docs/pc-only.md)）。
> 同梱のデモデータ・サンプルはすべて架空のものです。

## 解決する業務課題

| 課題 | このアプリでの対応 |
|---|---|
| 不要な作業まで、そのまま自動化してしまう | AI業務改善診断で、廃止→簡素化→標準化→自動化の順に見直す。自動化ありきの提案はしない |
| 毎月同じExcelの集計・照合に時間がかかり、手順が担当者の頭の中にある（属人化） | 処理手順を画面で組み立てて保存し、翌月は新しいファイルを選ぶだけで再実行する |
| VLOOKUP などの結合で、照合漏れや重複に気づかず、誤った集計を報告してしまう | 結合・集計を検証し、業務の「完了基準」（合計の一致・件数・対象期間など）で結果を判定する。重大な問題があれば正式な出力を止める |
| AIの答えが正しいか分からない | AIの根拠を「データで確認」「あなたの回答」「AIの推測」に分けて示し、データの根拠はサーバーで材料と照らし合わせる。採用するかは人が決める |

## 主要機能

| 機能 | 内容 | 状態 |
|---|---|---|
| AI業務改善診断 | 送る情報を確かめる → AIからの質問（3問まで・回答は任意） → 改善提案（重要な順に3件まで。根拠を3種類に分けて表示）→ 採用・保留・不採用 → 手順への反映の計画。判断と理由は作業手順のファイルに残し、次の診断で同じ質問をしない | 実装済み（AIの設定が必要） |
| 作業手順の作成 | ひな形から作る、または処理部品（読み込み・絞り込み・並べ替え・列の取り出し／名前の変更／削除・形式の変換・重複・空欄・結合・縦の連結・集計・計算・出力など15種類）を組み合わせて作る | 実装済み |
| 業務の完了基準 | 「何を満たせば完了か」を12種類の基準（必要な列・空欄なし・重複なし・合計の一致・件数・照合できない行・前回からの変化など）で設定。処理手順から基準の候補を提案（AIは使わない） | 実装済み |
| 品質検証と判定 | 実行ごとに、標準の確認（結合での行の増加・照合漏れなど）と完了基準を評価し、正常／注意／重大を判定。重大なら正式な出力を止める | 実装済み |
| 保存と再実行 | 作業手順をJSONファイルで保存し、次回は新しいファイルを割り当てて再実行。列構成の変化を実行前に検出 | 実装済み |
| データの分析 | 実行結果から主要数値、分類ごとのランキングと構成比、日付ごとの推移をグラフで示し、前回と比べて注目すべき変化（増減の率と量の両方が大きいもの）を挙げる。AIを使わない計算で、原因は断定しない | 実装済み |
| 前回との比較・履歴 | 前回の実行結果や前回のExcelと比べ、品質検証の履歴（どの版のルールで、どのデータを確かめたか）を残す | 実装済み |
| Excel出力 | 処理結果・確認結果・処理の記録をExcelに出力 | 実装済み |
| デモ | 3つの架空の業務（月次売上集計・商品マスタ照合・在庫差異検出）で、正常終了と品質異常を体験。業務改善診断デモ「その集計、本当に必要？」（AIは使わない） | 実装済み |
| AIによる作業手順の作成・AIによる分析コメント・無人定期実行 | — | 開発中（画面に「開発中」と表示し、使えるように見せない） |

## 使用技術

| 分野 | 技術 | 選んだ理由 |
|---|---|---|
| 画面 | React 19 / TypeScript / Vite / Tailwind CSS 4 / Zustand（状態管理）/ TanStack Query（通信） | 型で誤りを早く見つけられ、部品ごとに作り直しやすい |
| サーバー | Python 3.12 / FastAPI / Pydantic v2 | 入力の形を Pydantic で厳密に確かめられ、Excel処理のライブラリが豊富 |
| Excel処理 | python-calamine（読み取り）/ openpyxl / xlsxwriter（書き出し） | 10万行の読み取りを 14〜18秒から 2.7秒に短縮（実測。[docs/performance.md](docs/performance.md)） |
| 処理エンジン | 自作（列ごとの値のリスト＋列の型） | 自動の型推定による「黙った変換」（00123→123、金額の小数化など）を避け、結合・集計の検証を1行単位で説明できるようにするため（[docs/architecture.md](docs/architecture.md) v1.4） |
| AI | Claude API（公式 `anthropic` SDK・構造化出力） | 応答を決まった形で受け取り、形が違えば使わない |
| テスト | pytest / Vitest / Playwright（E2E） | サーバー・画面の部品・実際のブラウザ操作の3段階で確かめる |

## AI機能の安全策

- **送る前に見せる**：AIに送る文章はサーバーで組み立て、画面にそのまま表示してから送る（画面から届いた文章は使わない）。個人情報と思われる列の値は送らない
- **使える人を限る**：AI使用パスワード（ハッシュで保存）、最後の利用から60分で期限切れ、15分に5回失敗すると受け付けない
- **費用の上限**：月の上限（初期値10ドル）と1時間あたりの回数。上限に達するとAIを呼ばずに理由を示す。同じ材料ならAIを呼ばずに前回の結果を返す
- **AIの答えを確かめる**：「データで確認」とされた根拠は材料と照らし合わせ、確かめられなければ「推測」として表示。手順に使える部品も一覧と照らし合わせ、ないものは取り除く。効果の数値は「推定」「仮定」の印を付け、根拠のない数値は出さない
- **AIなしでも使える**：AIが設定されていなければ「利用できません」と示し、AIを使わない手順の作成へ案内する。テストでは実際のAIを決して呼ばない

## 開発の進め方と役割分担

このアプリは、生成AI（Claude Code）と対話しながら開発しています。

| 担当 | 行ったこと |
|---|---|
| 開発者本人 | 解決する業務課題と製品の方針の設定（「自動化する前に見直す」）、画面の仕様の指示（例：画面下部の主要な操作は1つにする、AIの質問は増やしすぎない）、設計上の判断（例：未設定の完了基準のうち重大なものだけ実行を止める、AIの診断に一本化する、実際のAIは自分でAPIキーを設定して確かめる）、実際のAIでの受け入れ確認 |
| 生成AI（Claude Code） | コード・テスト・設計資料の作成、選択肢と推奨案の提示、テストの実行と結果の報告 |

判断の記録は [docs/implementation-plan.md](docs/implementation-plan.md) に、日付・内容・テスト結果とともに残しています。

## 使い方

### 必要なもの
- Python 3.12
- Node.js 24

### バックエンドの起動（Windows / PowerShell）

```powershell
cd backend
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

2回目からは、プロジェクトのフォルダで `.\start-backend.cmd` を実行して起動できます（エクスプローラーでダブルクリックしても起動します）。
起動する前に、ポート8000に古いバックエンドが残っていないかを確かめ、残っていれば一覧を出して、止めるかを聞きます（勝手には止めません）。
起動するときに、AIの状態（off：使わない／fixed：固定応答／live：実際のAI）も表示します。
`.\start-backend.cmd -Check` は、確かめるだけで、止めも起動もしません。

ブラウザで http://127.0.0.1:8000/api/health を開き、`"status":"ok"` と表示されれば起動できています。
API仕様の一覧は http://127.0.0.1:8000/docs で確認できます。

### 画面（フロントエンド）の起動

バックエンドを起動したまま、別のターミナルで：

```powershell
cd frontend
npm install
npm run dev
```

> **「このシステムではスクリプトの実行が無効になっている」と表示された場合**
> PowerShellの安全設定により `npm.ps1` が止められています。次のどちらかで解決できます。
> - `npm` の代わりに `npm.cmd` を使う（例：`npm.cmd run dev`）
> - `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` を一度実行する（自分のユーザーにだけ適用。会社PCでは社内ルールを確認）

ブラウザで http://localhost:5173 を開きます。画面からの `/api/...` の呼び出しは、開発サーバーがバックエンドへ中継します。

### AI機能を使うとき（任意）

AIを使わない機能（Excelの読み込み・加工・集計・品質検証・出力・保存・デモ）は、この設定なしで使えます。
AIの設定がないときは、AIの操作は「AI機能は現在利用できません」と表示し、AIなしで手順を作るよう案内します（AIを使えるように見せません）。

1. AnthropicのAPIキーを用意します（費用が発生します。このアプリ専用のキーを作り、有効期限を短めにすることを勧めます。キーは他人に見せず、ソースコードやリポジトリに書かないでください）
2. AI使用パスワード（8文字以上）のハッシュ（元のパスワードに戻せない値）を作ります。入力した文字は画面に表示されません：
   ```powershell
   cd backend
   .venv\Scripts\python.exe -m app.ai.password
   ```
3. `backend/.env.example` を `backend/.env` に写し、APIキーと、手順2で表示された `AI_PASSWORD_HASH=...` の行を書きます（`.env` はGitで公開されない設定です）
4. `.\start-backend.cmd` で起動し直し、「AIの状態：live」と表示されることを確かめます

- 月の費用の上限は `AI_MONTHLY_BUDGET_USD`（初期値10ドル）、1セッションの1時間あたりの回数は `AI_CALLS_PER_HOUR`（初期値20回）で変えられます。上限に達すると、AIを呼ばずに理由を表示します
- パスワードの入力は、AIを使う操作のときだけ求めます。最後にAIを使ってから60分（最長8時間）で切れます。15分に5回失敗すると、しばらく受け付けません
- 開発・テスト用の固定応答モード（AIを呼ばない・費用なし）は `AI_MODE=fixed` で選べます

## 困ったとき

### 「サーバーが古い版のまま動いています」と表示される（デモが HTTP 404 になる）

開発用のサーバー（ポート8000）が、古いプログラムのまま動いています。Windows では `--reload` 付きで起動したサーバーを止めても、
実際に処理をしている**子プロセスが残り、ポート8000を使い続ける**ことがあります（2026-11-16・11-17 に確認）。
新しく起動すると古いものと2つが同時に待ち受け、古いプログラム・古い設定（`.env` を読む前など）のまま答えることがあります。

いちばん簡単なのは、バックエンドを止めてから、プロジェクトのフォルダで `.\start-backend.cmd` を実行することです。
残っているプロセスの一覧（起動役・待ち受け・子プロセス）が出るので、`y` を入力すると止めてから起動し直します。

手で止めるときは、次の手順で止めてから起動し直してください。

```powershell
# 1. ポート8000を使っている古いプロセスを確かめる（コマンドの中に multiprocessing.spawn とあるものが子プロセス）
Get-CimInstance Win32_Process | Where-Object { $_.Name -eq 'python.exe' } | Select-Object ProcessId, CreationDate, CommandLine

# 2. 古いもの（起動日時が古いもの）を、番号を指定して止める
Stop-Process -Id <番号>

# 3. backend フォルダで起動し直す
cd backend
.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

止めたあと、画面上部の「もう一度確かめる」を押して、表示が消えれば解決です。

## テスト方法

| 種類 | 件数（2026-11-17 時点） | コマンド |
|---|---|---|
| サーバー（pytest） | 623件 | `cd backend` → `.venv\Scripts\python.exe -m pytest -q` |
| 画面の部品の単体テスト（Vitest） | 201件 | `cd frontend` → `npm test` |
| 型チェック・ビルド・コードチェック | — | `cd frontend` → `npm run build` → `npm run lint` |
| E2E（実際のブラウザで画面を操作。Playwright） | 108件 | `cd frontend` → `npx playwright install chromium`（初回のみ）→ `npm run test:e2e` |

- テストは正常な操作だけでなく、入力の誤り・ファイルの列の不足・AIが使えないとき・AIが形の違う答えを返したときなども確かめています
- E2E は、テスト専用のサーバーをポート8001・5174で自動起動します（普段の開発用サーバーを起動したままでも実行できます）。画面は組み立て済みのもの（`vite build` → `vite preview`）で動かします。**テスト用のサーバーは、`.env` にAPIキーがあっても実際のAIを使わない設定で起動します**
- E2E の全件実行は、2並列で約5分です（2026-11-17 の実測：108件すべて成功）。パソコンの空きメモリが少ないと、テスト用のサーバーが起動できないことがあります

## データの取り扱い

- 読み込んだファイルと実行結果は、サーバーのメモリ上にだけ置き、最後の操作から60分で自動的に削除します。データベースやファイルには保存しません。
- 保存した作業手順（処理の手順・列名・条件の値・改善の記録）と実行の履歴（件数・合計などの集計値）は、ブラウザと、利用者が保存したファイルに残ります。Excelの中身は含みません。
- AIに送るのは、AI業務改善診断のボタンを押したときだけです。送る内容（作業の名前と目的・作業手順・品質ルールの名前・列名と形式・件数・範囲・各列の値の例3つまで・回答・前回までの診断）は、送る前に画面に表示します。個人情報と思われる列の値は送りません（判定は完全ではありません）。
- 公開環境では、機密情報や実在する個人情報を含むファイルは使用しないでください。

## 改善余地

| 項目 | 内容 |
|---|---|
| 業務での効果の実測 | 処理時間は実測済み（10万行で3.7〜5.5秒）だが、**業務の作業時間がどれだけ減るかは未測定**。デモに出てくる「毎月90分」などは架空の業務シナリオの値 |
| AIの提案の質の評価 | 実際のAIでの確認は、架空の業務で最後まで動くこと（提案まで30秒以内）の確認にとどまる。提案の妥当性を評価する仕組み（評価用の事例集）はない |
| E2Eテストの安定性 | 画面を組み立て済みのものに替え、全件実行で108件すべて成功（1回の実測）。テストごとに個別に延ばした待ち時間（20〜30秒）が多く残っており、整理の余地がある |
| 開発中の機能 | AIによる作業手順の作成、AIによる分析コメント、無人定期実行（設計のみ） |
| 公開 | 公開環境（Docker など）での動作は未確認 |
