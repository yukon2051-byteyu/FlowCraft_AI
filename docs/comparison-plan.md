# 生成AIとの比較評価計画（comparison-plan.md）

- 版：v0.1（2026-11-12）案
- 目的：ChatGPT・Claude などの生成AIに直接Excel作業を頼む場合と、FlowCraft AI を使う場合を、**公平に**比べる
- 実施時期：FlowCraft AI 側の機能（Phase 1・2、カイゼン支援の MVP）ができてから（Phase 9）。**実施するまで、優位性を事実として書かない**

## 1. 公平にするための決まり

| 決まり | 内容 |
|---|---|
| 生成AIの機能を制限しない | ファイルのアップロード、Pythonの実行（コード実行機能）、表やグラフの作成を使ってよい |
| 指示の書き方を2通り試す | ①普段の指示（例：「この3つのファイルで部署別の売上を集計して」）②よく考えた指示（検証も明示的に頼む：「結合で重複が起きないか、集計前後の合計が一致するか確認して」） |
| 同じデータ | 架空のデモデータ（backend/app/demos、仕込んだ問題の件数が分かっている） |
| 記録 | 使ったサービス名・モデル名・日付、全操作の所要時間、指示の回数、出力物を保存 |
| 実施者 | 2種類：Excelに詳しい一般事務の想定者、社内SEの想定者。可能なら筆者以外も |
| 結果の書き方 | 実測値と所感を分ける。FlowCraft AI が劣った項目も必ず書く |

## 2. シナリオ

| # | 種類 | 内容 | 仕込んだ問題 |
|---|---|---|---|
| S1 | 単発 | 売上実績（10月）＋商品マスタ＋部署マスタから、部署別・カテゴリ別の売上を集計し、Excelで出力 | なし（基本の操作性を見る） |
| S2 | 単発（問題あり） | S1 と同じだが、商品マスタに重複のあるファイルを使う | 商品コードの重複（売上が二重に数えられる） |
| S3 | 定型 | 翌月：S1 と同じ作業を11月のファイルで行う | 列名の変更、列順の変更、商品コードの空欄3件、マスタにないコード4件、末尾の空白2件、期間外の日付1件 |
| S4 | 改善 | 不要なステップ（読み込み直後の列削除、連続した絞り込み、集計前の並べ替え）を含む手順を見直す | 見直せる箇所3つ |

## 3. 評価項目

| 項目 | 測り方 |
|---|---|
| 操作の簡単さ | 指示・操作の回数、迷った箇所（観察記録） |
| 完了までの時間 | 開始から、正しい結果のExcelを得るまでの実測時間 |
| 検証の網羅性 | 仕込んだ問題のうち、**利用者が気づけた**件数（ツールが内部で検出しても、利用者に伝わらなければ数えない） |
| 誤った結果 | 誤った数字のまま「完了」と判断したか |
| エラーへの対応 | 問題が見つかったとき、原因と直し方が分かったか |
| 手順の修正しやすさ | 一部の条件を変える（例：部署を1つ除外）のにかかった時間 |
| 再利用のしやすさ | S3 で、S1 の作業をもう一度行うのにかかった時間と指示の回数 |
| 改善案の具体性 | S4 で、具体的な工程と理由を示せたか、実際の手順に反映できたか |
| 改善効果の測定 | 変更前後の時間・ステップ数・結果の一致を、根拠つきで示せたか |

## 4. 予想（検証する仮説。現時点では事実ではない）

| 仮説 | 根拠 |
|---|---|
| S1 の速さは、生成AIと同程度か、生成AIのほうが速い | 生成AIはファイルを渡せばすぐ集計できる |
| S2・S3 の「気づけた問題の数」は、普段の指示の生成AIより FlowCraft AI が多い。よく考えた指示の生成AIとは差が小さい | 検証が最初から付くか、頼む必要があるかの違い |
| S3 の再実行の時間は FlowCraft AI が短い | 保存した手順を使うため |
| S4 は、改善の指摘自体は生成AIもできる。反映と前後の比較の手間で差が出る | §9（kaizen-design.md） |

結果は `docs/comparison-results.md` に記録する。仮説と違った場合も、そのまま記録する。
