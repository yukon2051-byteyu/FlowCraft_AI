# 性能測定の記録（performance.md）

測定スクリプト：[backend/scripts/perf_benchmark.py](../backend/scripts/perf_benchmark.py)（架空データを生成して測定。乱数シード固定）
測定環境：Windows 10 / Python 3.12.10 / 開発用PC（ほかの処理と並行して実行しているため、数秒程度の揺れがある）

## 測定条件

売上 100,000行 × 8列（xlsx 3.4MB / csv 4.3MB）、商品マスタ 1,000行、部署マスタ 18行。
フローはデモA相当（読込3・列の抽出・結合2・集計2・出力）。

## 結果（2026-11-12）

| 工程 | 改善前 | 改善後 | 目標（10秒以内） |
|---|---|---|---|
| 1. Excel読み取り（openpyxl） | 17.0秒 | 14.1〜18.3秒（変更なし） | ❌ **未達**（下記「判断待ち」） |
| 2. 構造解析（見出し・型推定） | 1.9秒 | 2.1秒 | ✅ |
| 3. CSV読み取り | 0.6秒 | 0.7秒 | ✅ |
| 4. 読込ノード（型変換） | 4.4秒 | 2.6秒 | ✅ |
| 5. デモA相当フロー全体 | **11.6秒** | **3.7秒** | ✅ |

### 行った改善

- **結果の指紋（SHA-256）を「出力する表」だけに計算**：途中の10万行の表4つにも計算しており、1つあたり約3秒かかっていた。再現性の確認に必要なのは出力だけのため。
- **指紋の計算を列ごとにまとめて行う**：値ごとに「型の印＋文字数＋文字列」を連結（区切りの曖昧さが生じない）。

## Excel読み取りの高速化（2026-11-12 採用・実装済み）

ユーザー確認（P1）のうえ、読み取りを `python-calamine` 0.9.1（Rust製・読み取り専用）に切り替えた。書き出し（タスク4-2）は openpyxl を使う。

| 項目 | openpyxl（旧） | 新方式 |
|---|---|---|
| 10万行の読み取り | 14〜18秒 | **2.7〜4.9秒**（calamine 約1.9秒＋値の整形 約1秒＋エラー値の検査） |

### openpyxl との違いと対処

| 違い | 対処 |
|---|---|
| 整数が float（2.0）で返る | 読み取り直後に int にそろえる（値は同じ） |
| 時刻のない日付が date で返る | datetime にそろえる |
| 空のセルが ''（空文字）で返る | None にそろえる |
| **エラー値（#N/A など）が '' になる** | エラー値のセルを含むファイルだけは openpyxl で読む（空欄扱いにして集計から黙って外れるのを防ぐ） |
| 行ごとの読み取り（iter_rows）は左の空列を詰めて返す | A1起点で行・列を補う `to_python(skip_empty_area=False)` を使う |

確認：`tests/test_xlsx_parity.py`（注意が必要な値・A1以外から始まる表・非表示/空のシート・計算結果のない式・エラー値・行数上限）で、両ライブラリの読み取り結果が値・型とも一致することを確認。
