# 空白データの確認と品質ルール 設計書（blank-data-design.md）

- 版：v0.1（2026-11-13 設計のみ。実装は未着手）
- 元の指示：MVP追加開発指示書「データ品質ルールの学習・再利用機能」（2026-11-13）
- 前提：[completion-criteria.md](completion-criteria.md)（完了基準・総合判定）、[scheduled-run-design.md](scheduled-run-design.md)（5段階の確認・設定の版と再検証）

---

## 0. 結論

1. **品質ルールは「作業手順（案件）」の中に保存する**（新しい保存の仕組みを作らない）。作業手順は、画面・クラウドの Worker・Windows Worker のすべてが同じファイル（JSON）を使うので、**どの実行方式でも同じルールが、同じコードで適用される**。ルールを変えると作業手順の内容が変わり、無人実行は自動で「要再検証」になる（設定の版の仕組みをそのまま使う）
2. 流れは指示どおり **自動検出 → 保存済みのルールで判定 → 判定できないものだけ、まとめて確認 → ルールとして保存 → 次回から自動で適用**。AIは使わずに動く（AIの判断支援は Phase 5 で上乗せし、提案として表示するだけ）
3. 既存の仕組みと重なる部分が多いため、**別の仕組みを並べず、今ある仕組みを広げる**（§2）
4. 作る時期は **Phase 2 の残り（2-4〜2-6）→ Phase 3 → この機能（Phase Q）→ M1 → S1（無人実行）**。無人実行の「品質検証」の段階がこの機能を使うため、S1 より前に作る

## 1. 今ある仕組みとの関係（重なりを整理する）

| 指示書の項目 | 今ある仕組み | この機能で足すこと |
|---|---|---|
| 必須列の欠損 | 入力の定義の「必ずある列」＝**列そのものがあるか**。完了基準「空欄がない」（2-1・2-2） | 「列はあるが、**値**が空欄」を列ごとに扱いを決める（許可／注意／止める／条件付きで許可） |
| 完全空白行 | 読み込みの確認で「表の途中に空の行がN行」と警告するだけ。末尾の大量の空行は読まない | 途中の空白行・末尾の空白行を区別し、「区切りとして除外／残す／止める」を決める |
| 欠損値の処理 | 処理ステップ「空欄の確認・行の除外・補完」（detect／drop／fill） | そのまま使う。ただし**無人実行の前に決めておくべき判断**は、ステップではなく入力のルールとして持つ |
| 品質検証の結果 | 完了基準の評価・総合判定（2-2・2-3） | 空白のルールの結果も総合判定に入れる（必須の欠損は重大、未定義の重要な空白は「未検証」→ 無人実行では止める） |
| 再検証 | 無人実行の設計：設定の指紋が変わったら要再検証 | ルールは作業手順の中にあるので、変えれば自動で指紋が変わる |

## 2. ルールの形（作業手順ファイル 1.2 の案）

入力の定義（`input_definitions[]`）に、空白の扱いを足す。**ルールは入力（ファイルの種類・シート）と列に結び付く**ため、関係のないファイルには適用されない。

```jsonc
{
  "input_id": "sales", "label": "売上実績", "file_kind": "xlsx", "sheet_hint": "売上",
  "blank_rules": {
    "version": 2,                          // ルールを変えるたびに +1（実行の記録に残す）
    "blank_rows": "skip",                  // 表の途中の完全空白行：skip（区切りとして除外）／keep（残す）／error（止める）／unset（未定義）
    "trailing_blank_rows": "ignore",       // 表の末尾の空白行：ignore（表の外とみなす。初期値）
    "whitespace_is_blank": true,           // 空白文字だけのセルを空欄として扱う
    "merged_cells": "fill_down",           // 結合セル：fill_down（結合範囲の値として扱う＝欠損にしない）／as_blank
    "changelog": [{ "version": 2, "changed_at": "…", "summary": "「部署」の空欄を重大に変更", "by": "利用者" }]
  },
  "columns": [
    { "name": "部署", "type": "string", "required": true,
      "blank": { "action": "critical" } },                         // 空欄なら止める
    { "name": "備考", "type": "string", "required": false,
      "blank": { "action": "allow" } },                            // 空欄を許可
    { "name": "売上", "type": "integer",
      "blank": { "action": "allow_if", "condition": { "column": "区分", "operator": "eq", "value": "返品" } } },  // 条件付きで許可
    { "name": "担当者", "type": "string" }                         // blank がない＝未定義（空欄が見つかったら確認する）
  ]
}
```

| action | 意味 | 無人実行での動き |
|---|---|---|
| allow | 空欄を許可 | 続行（件数を記録） |
| caution | 空欄があれば注意 | 続行し、注意として知らせる（運用ルールにより正式出力を止める：scheduled-run-design.md S-3） |
| critical | 空欄があれば止める（必須項目） | **停止**。正式な出力をしない |
| allow_if | 条件に合う行だけ空欄を許可 | 条件に合わない空欄は critical として扱う |
| manual_fix | 手で直すまで処理しない | **停止** |
| （未定義） | まだ決めていない | 画面：確認を求める／**無人実行：停止・要確認**（AIは独断で直さない） |

- **空欄を 0 に置き換えることはしない**。補完が必要なら、既存の処理ステップ「空欄の補完」で、利用者が値を明示して行う
- 元のファイルは書き換えない。除外・止めた理由と件数は、実行の記録に残す（読み込んだデータのコピーに適用する）

## 3. 検出（読み込みの段階）

| 空白の種類 | 検出の方法 | 状況 |
|---|---|---|
| 完全空白行（途中） | 見出しの下〜最後のデータ行の間で、すべてのセルが空 | 今の読み込みで数えている。行番号の記録を足す |
| 完全空白行（末尾） | 最後のデータ行より後 | 今の読み込みで取り除いている（表の外として扱う） |
| 一部の空欄 | 列ごとの空欄の件数・行番号 | 今の読み込みで数えている（列の情報） |
| 空白文字だけのセル | 値が空白文字だけ | **確認済み（B-4）**：実際の Excel のファイルでは、calamine は半角スペース3個をそのまま読む（試作ファイルで消えたのは、試作に使ったライブラリの保存の仕方のため）。**今の読み込みは、これを「値がある」と数えている** → Q-2 で空白として扱う |
| 数式が空の文字列を返すセル | 数式の有無は、今の読み込み方法では分からない | **確認済み（B-4）**：calamine は空の文字列を返す数式（F7 `=IF(A7="","",A7)`）を、普通の空欄と同じ「''」として読む。openpyxl（数式を読む設定）なら数式があると分かる。10万行での速さは Q-2 で測ってから方式を決める |
| 結合セル | 結合範囲の情報（calamine の `merged_cell_ranges`） | **確認済み（B-4）**：A1:G1（表題）と A9:B9 の両方を取得できる。結合範囲の2つ目以降のセルは欠損にしない |
| CSV | 結合・数式はない。空白文字だけのセル・空行は判定できる | 同じ規則を使う（Excel だけの項目は対象外） |

**B-4 のサンプルで見つかった、今の読み込みの問題（2026-11-13）**

| 問題 | 内容 | 影響 | 対応 |
|---|---|---|---|
| 見出しの行の推定 | 1行目の表題（A1:G1 を結合）を見出しと推定し、本当の見出し（3行目）を選ばない | 列名が「列B」などになる。利用者が見出しの行を3にすれば正しく読める | Q-2：結合した表題の行と、その下の空行を飛ばして推定する |
| 合計・メモの行 | 9行目「集計メモ」（売上 300,000 ＝ 上の3行の合計）を、データの行として読む | **集計すると売上が二重に数えられる**（標準の確認では気づけない） | Q-2：最後の行の数値が上の行の合計と一致する場合など、「合計・メモの行の可能性」として確認を求める |
| 空白文字だけのセル | 「   」を値として数える | 空欄の確認をすり抜ける | Q-2：空白として扱う（`whitespace_is_blank`） |

**見出し・注釈・合計行との区別**：対象のデータ範囲は「見出しの行の下から、最後のデータ行まで」。表の下の注釈・合計行は、今の見出しの判定と同じく利用者が範囲を確かめる（1-2・1-9 の画面）。MVP では「表の下に、空白行を挟んで別の内容がある」場合に注意として知らせ、自動では除外しない。

## 4. 確認の画面「空白データの確認」

- 出るのは、**新しく作る（1-2）・ファイルを割り当てる（1-9）ときに、ルールが未定義の空白が見つかったときだけ**。保存済みのルールで判定できるものは聞かない
- 同じ原因のものは**まとめて1回**聞く（例：「部署」の空欄 3件 → 1つの質問。途中の空白行 5行 → 1つの質問）
- 表示：ファイル名・シート・列・空白の種類・件数・例の行と前後の行・おすすめの対応と理由・判断が必要な理由
- おすすめは**決まった規則**で出す（例：「必ずある列」の空欄 → 止める、を提案。途中の空白行がほぼ一定の間隔 → 区切りの可能性、を提案）。AIの提案（Phase 5）は「AIの提案」と明記し、不確かさと理由を示し、承認するまでルールにしない
- 決めた内容は、作業手順のルールとして保存し、変更の記録に残る

## 5. 結果の表示と総合判定

- 結果の画面に「データ品質の確認」を出す：入力件数、完全空白行（除外した件数）、許可した空欄、必須項目の欠損、未解決の確認事項、判定
- 総合判定への反映：必須（critical）の欠損 → **重大**。未定義の空白 → **未検証**（画面では確認を求め、無人実行では止める）。caution → 注意
- 表示の優先順位：止める重大な問題 → 判断が必要なこと → 自動で適用したルール → 詳しい検出結果（大量の空欄は1件ずつ出さず、列ごとにまとめる）

## 6. 無人実行（クラウド・Windows）

| 状況 | 動き |
|---|---|
| 許可した空白 | 続行 |
| 区切り行として除外と決めた空白行 | 除外して続行（件数を記録） |
| 必須項目の欠損 | 停止（正式な出力をしない） |
| 未定義の重要な空白 | 停止・要確認 |
| ルールの矛盾（例：同じ列に「許可」と「止める」） | 作業手順の検証で保存させない。万一あれば停止 |

5段階の確認の「品質検証」では、未定義のまま残っている空白（テスト実行で見つかったもの）があると有効化できない。
