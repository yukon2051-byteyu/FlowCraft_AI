# 画面の用語集（ui-terminology.md）

- 対象：専門用語の排除と操作説明の改善指示
- 版：v1.1（2026-11-12・T1「段階」で確定、既存の全画面とサーバーのメッセージに適用済み）
- 適用範囲：一般ユーザー向けのすべての画面（TOP・ファイル読込・AIへの指示・作業手順の編集・分析・品質検証・Excel出力・保存・再実行・デモ）。開発者向け診断画面と、ソースコード内の命名（node・flow など）は対象外

## 1. 基本用語

| 内部・技術用語 | 画面での表現 | 補足（初出時の短い説明） |
|---|---|---|
| フロー | **作業手順** | 「Excel作業の手順を、上から順に並べたもの」 |
| ノード | **処理ステップ**（文中では「ステップ」） | 「作業手順の1つ1つの作業」 |
| ノード追加 / 削除 | 処理を追加 / 処理を削除 | |
| ノード設定 | 処理内容を確認・変更 | |
| フロー実行 | 作業を実行 | |
| フロー保存 / JSON保存 | 作業手順を保存 / 作業手順をファイルに保存 | 「保存したファイルを開けば、翌月も同じ作業を実行できます」 |
| フロー読込 | 保存した作業手順を開く | |
| プレビュー | 処理前・処理後のデータを見る | |
| 確定 | 確認済み | |
| AI提案 | AIの提案（未確認） | |
| 確認待ち | 回答が必要 | |
| 未設定 | 設定が必要 | |
| 結合キー | 照合に使う列（例：商品コード） | |
| 未照合 | 相手の表に見つからない | |
| 型 | データの形式（文字・数値・日付など） | |
| セッション | （表示しない）「読み込んだデータは60分で自動削除」とだけ表示 | |

### 画面上部の進み具合の呼び方（確認事項 T1：「段階」で確定）

「処理ステップ」と区別するため、画面上部の5つの段階は「**段階**」と呼ぶ。
例：「段階3：作業手順を確認する」「ステップ4『部署マスタの情報を付け加える』の確認が必要です」

## 2. 処理の名前（処理ステップの種類）

| 内部名 | 画面の名前 | 一覧での説明の例（設定内容から自動で作る） | 詳細設定での正式名 |
|---|---|---|---|
| load | ファイルを読み込む | 「売上実績.xlsx」の「売上」シートを読み込む | 読込 |
| filter | 条件に合う行だけ残す | 金額が1,000円以上の行だけ残す | 行の抽出 |
| sort | 並べ替える | 金額の大きい順に並べ替える | 並べ替え |
| select_columns | 必要な列を取り出す | 売上日・商品コード・金額の3列を取り出す | 列の抽出 |
| rename_columns | 列の名前を変える | 「売上金額」を「金額」に変える | 列名の変更 |
| drop_columns | 不要な列を消す | 「備考」「担当者」を消す | 列の削除 |
| add_constant | 同じ値の列を追加する | 「対象月」列を追加（全行 2026/10） | 固定値列の追加 |
| cast | データの形式をそろえる | 「金額」を数値にそろえる | 型変換 |
| duplicates | 重複を調べる / 重複を取り除く | 伝票番号の重複を調べる | 重複処理 |
| missing | 空欄を調べる / 空欄を埋める / 空欄の行を除く | 「数量」の空欄を0で埋める | 欠損値処理 |
| join | 別の表から情報を付け加える | 商品コードを使って、商品マスタの商品名を付け加える | データ結合 |
| concat | 複数の表を縦にまとめる | 東京・大阪・名古屋の表を1つにまとめる | データ連結 |
| aggregate | 項目ごとに合計・集計する | 部署ごとに金額を合計する | グループ別集計 |
| calculate | 計算した列を追加する | 「数量 × 単価」で「金額」を計算する | 計算列 |
| output | Excelに出力する | 「部署別売上」など3シートを出力する | Excel出力 |

## 3. AIからの確認の書き方

技術的な質問をそのまま出さず、**①何を確認したいか ②なぜ確認するのか（リスク） ③回答による違い** をそろえる。

| 悪い例 | 良い例 |
|---|---|
| 商品マスタの結合キーはユニークですか？ | 商品マスタに同じ商品コードが複数あると、売上が重複して集計されるおそれがあります。**商品コードは1商品につき1つだけですか？**<br>・はい → そのまま商品名を付け加えます<br>・いいえ → 実行前に重複している商品コードの一覧を表示します |
| 未照合レコードの扱いは？ | 売上にあって商品マスタにない商品コードがあった場合、どうしますか？<br>・警告を出して続ける（売上の行は消しません）<br>・作業を止める |

## 4. 次の操作の案内（例）

| 状況 | 表示 |
|---|---|
| ファイル未読込 | 処理に使うExcel・CSVファイルを読み込んでください |
| AIの確認待ちあり | ステップ3の確認が必要です。商品コードの重複について回答してください |
| 未確認のステップあり | AIの提案を確認してください（残り2ステップ） |
| すべて確認済み | すべての処理内容を確認しました。作業を実行できます |
| 実行で問題 | ステップ4で問題が見つかりました。内容を確認してください |
| 実行完了 | 作業が完了しました。結果を確認し、Excelに出力してください |

押せないボタンには、理由をマウスを重ねたときの説明と、ボタンの近くの文で示す（例：「確認が終わっていないステップが2つあるため、まだ実行できません」）。
