# 分析エンジン・結果レポート 設計書（analysis-design.md）

指示書「実行結果・品質検証・データ分析レポート統合開発」（2026-11-13）と確認事項 R-1〜R-7（推奨どおりで確定）による。

## 0. 結論

| 項目 | 決めたこと |
|---|---|
| 置き場所（R-1） | `backend/app/analysis/`。**AIを使わない計算だけ**。結果は実行の記録（RunRecord）に入れ、単発・再実行・無人実行で共通 |
| 何を分析するか（R-2） | 「同じ値ごとにまとめる」ステップの設定から決める（まとめる列＝分類、合計・件数＝数値）。列名から意味を推測しない |
| 比較用ファイル（R-3） | 同じ作業手順を比較用ファイルで別に実行して記録を作り、比べる。データは混ぜない。ファイル数の上限に含める（Phase B） |
| グラフ（R-4） | 新しいライブラリは使わない。画面は SVG の棒・折れ線、Excel は xlsxwriter のグラフ。1つのレポートで最大3つ |
| 注目すべき変化（R-5） | 増減率と増減の量の**両方**が閾値を超えたものだけ。初期値：率 20%以上 かつ 量（件数 10件以上／金額 前回合計の1%以上）。品質判定には入れない（完了基準として設定したときだけ反映：QM-2 の12種類目） |
| AIコメント（R-6） | Phase 5 の後。それまでは「開発中」 |

## 1. 分析の中身（Phase A）

| 区分 | 内容 | 出どころ |
|---|---|---|
| 基本集計 | 出力する表ごとの件数、数値の列の合計・平均・最大・最小 | 出力する表 |
| ランキング・構成比 | まとめるステップごと：まとめた値の上位5件と構成比（全体に占める割合）、残りの件数 | まとめるステップ（まとめる列が1つで、合計か件数があるもの） |
| 時系列 | まとめる列が日付のとき、その順に並べた推移 | まとめるステップ |
| 分析できないこと | 「まとめる集計がないため、ランキング・構成比は表示しません」など、理由を示す。空のグラフや不自然な 0 は出さない | — |
| 注目すべき変化 | 前回（業務の数値の相手：QM-2 の選び方）の同じ分類の値と比べ、§0 の閾値を両方超えたもの | 前回の記録の分析 |
| 確認すべきこと | 品質の判定の理由と、注目すべき変化から、決まった文で作る。原因は断定しない（「〜がないか確認してください」） | 判定・注目すべき変化 |

- 数値は Decimal で計算し、文字列で返す（小数の誤差を出さない）。割合の分母が 0 のときは割合を出さない
- 記録に入れるのは集計済みの値だけ（分類ごとの値は最大50件）。元の行は入れない

## 2. 作る順番

| 段階 | 内容 |
|---|---|
| **A** | 分析エンジン（基本集計・ランキング・構成比・時系列・注目すべき変化・確認すべきこと）。実行 API と記録に入れる |
| B | 結果の画面（実行結果・品質判定・主要数値を上に、前回比較・分析・品質の詳細・確認すべきことを下に。詳細は開閉式）、比較用ファイル、Excel の「確認結果」への追加（＋必要なら「データ分析」シート1枚） |
| C | ブラウザの履歴（IndexedDB。QM-3）と前回比較の画面 |
| F | デモへの反映と E2E |
| （後） | D：Worker への統合（S1）／E：AI コメント（Phase 5 の後） |
