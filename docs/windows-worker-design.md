## 0. 結論

1. **MVP では、Worker が自分の PC の中で管理画面（Web 画面）を開く方式（方式A）にする**。初回のセットアップ後は、デスクトップの「FlowCraft Worker」を開けば、ブラウザで案件の追加・変更・有効化・履歴の確認ができる。画面は公開サイトと同じ FlowCraft AI の画面（作業手順の作成・保存・読み込みもそのまま使える）
2. **業務ファイルも案件の設定も、PC の外に出ない**。管理画面は PC の中だけで開ける（127.0.0.1）。クラウドの DB とローカルの SQLite はつながない
3. 公開サイトで作った作業手順は、「作業手順を保存（.json）」→ 管理画面の「作業手順を開く」で Worker に渡す（1-8・1-9 の機能をそのまま使う）
4. 起動は **Windows タスクスケジューラに「1分ごと」のタスクを1つだけ**登録する。3分後の実行は、予定から**最大90秒ほど遅れる見込み**（実測して記録する）
5. 読み書きできるフォルダは**利用者が許可したフォルダだけ**（初期値 `C:\FlowCraft\input` と `C:\FlowCraft\output`）
6. 配布は **`FlowCraft Worker.exe`（PyInstaller）を zip で**。初回起動のセットアップで、フォルダ作成・タスク登録・デスクトップのショートカット作成まで行う

## 1. 開発・検証の環境について（重要）

- この開発に使っている PC は **Windows 10 Pro**。タスクスケジューラ・PowerShell の仕組みは Windows 11 と同じため、ここで作って確かめる
- **Windows 11 での最終確認（完了条件の 1〜10）は、利用者の Windows 11 PC で行う必要がある**。確認の手順書を用意し、結果を記録してもらう（実施していない確認を「確認済み」と書かない）

## 2. Web 画面と Worker のつなぎ方（指示書 §4 の回答）

| 方式 | しくみ | 業務データ | 難しさ・危険 | 評価 |
|---|---|---|---|---|
| **A. Worker が PC の中で管理画面を開く** | exe の中に FlowCraft AI の画面とサーバーを入れ、`http://127.0.0.1:8765` で開く。案件は PC の SQLite に保存 | PC の外に出ない | 低い。インターネットに公開しない | **MVP で採用** |
| B. 公開サイトが中継する | 公開サイトに案件を保存し、Worker が HTTPS で取りに来る（ペアリング・Worker 専用の鍵） | ファイルは出ないが、フォルダの場所・案件名・履歴はクラウドへ | **公開サイトにログインの仕組みが必要**。クラウドが乗っ取られると PC 上の処理を操作される危険 | 製品版（複数拠点の集中管理）の候補。指示書 §5 で MVP 対象外 |
| C. 公開サイトの画面から、同じ PC の Worker へ直接送る | ブラウザが公開サイトから `127.0.0.1` を呼ぶ | 出ない | Chrome・Edge の「ローカルネットワークへのアクセス」の許可や制限が更新で変わりやすい。悪意あるサイトからの呼び出しを防ぐ作りが複雑 | 不採用（MVP では安定して動かせる保証がない） |

**方式A の安全対策**

| 危険 | 対策 |
|---|---|
| 同じネットワークの他の PC から管理画面を開かれる | `127.0.0.1` だけで待ち受ける（外から届かない） |
| 悪意あるサイトが、ブラウザを通して管理画面の API を呼ぶ | ① 管理画面は Worker が発行した**合言葉付きのリンク**を開いたときだけ使える（合言葉はインストールごとの乱数。PC の利用者のフォルダに保存）② API は `Host` と `Origin` が `127.0.0.1:8765` のときだけ受け付ける（DNS の書き換えを使った攻撃を防ぐ）③ 変更する操作には画面ごとの確認用の値（CSRF 対策）を付ける |
| 案件の設定で、関係のないフォルダを読み書きされる | 読み書きは「許可したフォルダ」の中だけ（§5） |
| 任意のプログラムを動かされる | 実行できるのは FlowCraft の作業手順（15種類の処理）だけ。外部のプログラム・URL は扱わない |

公開サイトと管理画面は、同じ画面のコードを使う。違いは「無人定期実行」の画面が使えるかどうか（公開サイトでは「Windows Worker をセットアップすると使えます」と案内する）。

## 3. 導入（セットアップ）を簡単にする

```text
1. 公開サイトの案内ページから FlowCraft-Worker.zip をダウンロード
2. zip を展開し「FlowCraft Worker.exe」をダブルクリック
3. 初回だけ、セットアップの画面が開く（ブラウザ）
   ・入力フォルダ・出力フォルダ（初期値 C:\FlowCraft\input / output）を確認 → 作成
   ・「自動実行を登録する」を押す → タスクスケジューラに1分ごとのタスクを1つ登録
   ・デスクトップに「FlowCraft Worker」のショートカットを作る
4. 以後は、ショートカットを開くと管理画面が開く
```

- 管理者の権限は不要にする（タスクは「ログオンしているときだけ実行」で、利用者自身のアカウントで登録）。「ログオフ中も実行」はパスワードの保存と管理者権限が必要なため、手順書で任意の設定として案内する
- **署名していない exe のため、初回に Windows の「PC が保護されました」という警告が出る**。正規の配布物かを確かめる方法（公開サイトに載せた指紋〔SHA-256〕と照合）を案内する。コード署名の証明書は有料のため MVP では使わない
- 削除：管理画面の「Worker を削除する」で、タスクの登録を消す。その後、フォルダを削除すれば元に戻る

## 4. 起動の間隔と遅れ

| 案 | 3分後の実行の遅れ | 評価 |
|---|---|---|
| **タスクスケジューラで1分ごとに起動**（起動するたびに実行対象を判定して終了） | 最大60秒＋起動に数秒 → **最大90秒ほどの見込み** | **採用**。共通Worker 方式どおり。落ちても次の1分で復帰する |
| Worker を常に動かし、10秒ごとに確認 | 最大10秒ほど | 常駐の管理（止まったときの再起動）が必要。精度が必要になったら追加 |

- タスクスケジューラの繰り返しは、1分が最小の間隔
- 「すでに実行中なら新しく起動しない」設定にし、さらに DB の一意制約で二重実行を防ぐ（2重の対策）
- PC がスリープ・電源 OFF の間は実行されない。復帰したときに、遅れの許容時間（初期値60分）以内なら実行し、過ぎていれば「実行漏れ（確認待ち）」にする（scheduled-run-design.md §6）。画面に明記する

## 5. 読み書きできるフォルダの制限

- 設定で許可したフォルダ（「許可フォルダ」）の中だけを読み書きする。初期値は `C:\FlowCraft\input`（読み取り）と `C:\FlowCraft\output`（書き込み）
- 案件で指定したパスは、実際の場所に直してから（`..` やショートカット・ジャンクションをたどった先も含めて）許可フォルダの中かを確かめる。外なら保存できない
- MVP では `\\サーバー\共有` の形（社内の共有フォルダ）は受け付けない（「製品版で対応予定」と表示）
- 出力は「一時ファイルに書く → 品質検証に合格 → 名前を変えて確定」。既存のファイルは初期値で上書きしない

## 6. 共通化（クラウドの Worker と同じコードを使う）

```text
app/engine  … 処理エンジン（共通）
app/export  … Excel 出力（共通）
app/quality … 品質検証・完了基準（Phase 2 で作る。共通）
app/jobs    … 案件の状態・設定の版・5段階の確認・実行対象の判定・実行権の確保・run_due_jobs（共通）
   ├ store/   SQLite（Windows）／ PostgreSQL（クラウド）
   ├ sources/ ローカルフォルダ（Windows）／ サンプルデータ（クラウドのデモ）
   └ triggers 1分ごとのタスク（Windows）／ QStash の合図（クラウド）
app/worker  … `python -m app.worker tick`（exe では `FlowCraft Worker.exe tick`）
```

- 案件の追加・作業手順の変更で、exe を作り直す必要はない（案件と作業手順は SQLite に保存）
- 処理の中で AI は使わない。ローカル版は外部へ通信しない（利用状況の送信もしない）

## 7. 公開サイトでの説明（利用者の指示による）

| 区分 | 内容 | 表示 |
|---|---|---|
| **今すぐ試せる** | クラウド上で3分後に Excel を自動実行（サンプルデータ） | 実装・公開・実測ができてから「今すぐ試せる」と表示。それまでは「開発中」 |
| **Windows Worker で試せる** | 自分の PC の Excel・CSV を、指定した時刻に自動処理。ブラウザを閉じていても、処理・品質検証・結果の保存まで実行 | 実装し、Windows 11 で確認できてから表示を切り替える。それまでは「開発中」 |
| **製品版で対応予定** | 社内共有フォルダのファイル取得・加工・保存、企業内サーバーでの無人定期実行 | 「対応予定」と明記（今使える機能と混同させない） |

## 8. 完了条件と確かめ方

| # | 完了条件 | 自動テスト（この PC） | 利用者の Windows 11 PC での確認 |
|---|---|---|---|
| 1 | Worker が起動する | exe の起動・`tick` の終了コード | ◯ |
| 2 | ローカルフォルダの Excel を読み込める | 一時フォルダで確認 | ◯（`C:\FlowCraft\input`） |
| 3 | 保存した作業手順で加工できる | 指紋と正解値で確認 | ◯ |
| 4 | 3分後に無人実行される | 時刻を指定した `tick` で確認 | ◯（実時間で。予定との差を記録） |
| 5 | ブラウザを閉じても実行される | ― | ◯ |
| 6 | 品質検証が動く | 異常データで正式出力しないことを確認 | ◯ |
| 7 | 結果の Excel が出力フォルダに保存される | 確認 | ◯ |
| 8 | 実行履歴が保存される | 確認 | ◯ |
| 9 | 二重実行が防止される | 2つの Worker を同時に動かして1回だけ | ― |
| 10 | 複数案件を1つの Worker で管理できる | 3案件で、対象だけが実行される | ◯ |

## 9. 作る順番

S1（M1 の後）の中で：共通部分（app/jobs）→ クラウドの3分後デモ → Windows Worker（管理画面・tick・セットアップ・exe）→ Windows 11 での確認（利用者）。

## 10. MVP で作らないもの（拡張できる形にしておく）

社内の共有フォルダ（SMB）、Active Directory との連携、複数拠点・複数企業の集中管理（方式B）、Worker の一括配布・自動更新、本番向けの監視。
