## 1. 方針

| 原則 | 実現方法 |
|---|---|
| 数値はPythonで計算し、AIに作らせない | 分析も既存の処理エンジンの「処理ステップ」として実装する。AIは条件の提案と、計算済みの数値の説明だけを行う |
| 分析条件も作業手順に保存し、再実行できる | 分析ステップは既存の作業手順（フローJSON）にそのまま入る。スキーマを 1.0 → 1.1 に上げ、1.0 は自動で読み込めるようにする |
| 既存機能を壊さない | 既存のステップ・API・画面には「追加」だけを行う。既存の全テスト（現在296件）を毎回実行する |
| データにない数値は作らない | 比較期間のデータがない場合は「算出不可（前期データなし）」とし、推測で補完しない |

### 2.2 追加する処理ステップ

| 内部名 | 画面上の名前（案） | 主な設定 | 出力 |
|---|---|---|---|
| `stats` | 基本の統計を出す | 対象の列、項目（合計・平均・中央値・標準偏差など）、グループ化する列 | 統計の表 |
| `compare` | 前の期間と比べる | 日付の列、比較の単位（前月比・前年比・任意の2期間）、比べる数値、グループ化する列 | 当期・前期・増減額・増減率の表 |
| `rank` | 順位をつける | 順位をつける数値、上位/下位、件数、同順位の扱い | 順位つきの表 |
| `share` | 割合（構成比）を出す | 割合を出す数値、グループ化する列 | 金額と構成比の表 |
| `timeseries` | 期間ごとの推移を出す | 日付の列、単位（日・週・月・年）、数値と集計方法 | 期間ごとの表（データのない期間も「0件」として表示するか選択） |
| `chart` | グラフにする | グラフの種類、横軸・縦軸、表示件数、並び順、数値の形式、単位 | グラフ定義（表は変更しない） |
| `ai_comment` | AIに解説してもらう | 対象とする分析結果、コメントの有無 | 解説文と根拠（Phase 2以降） |

### 2.3 計算ルール（確定済みの内容は指示書どおり）

- 増減率 ＝（当期 − 前期）÷ 前期 × 100。**前期が0、または前期データがない場合は「算出不可」**（理由を区別して表示）
- 構成比 ＝ 各項目 ÷ 合計 × 100。合計が0なら算出不可。**値は丸めずに計算し、表示だけ小数1桁**。表示上の合計が100.0%にならない場合は「丸めによる表示上の差」と注記する（値を調整して100%に合わせることはしない）
- 中央値・標準偏差は Decimal で計算し、空欄は除外（件数を表示）
- 時系列の日付変換に失敗した値は件数と行番号を示す（既存の型変換と同じ）

## 3. AI分析コメントの安全設計（Phase 2 以降）

1. 計算済みの分析結果を「根拠ID付きの指標一覧」（例：`m3：営業1部の前月比 +12.4%`）にしてAIへ渡す
2. AIには「根拠IDを付けて文章を書く」「一覧にない数値を書かない」ことを構造化出力で指示する
3. 生成された文章の**数値をすべて抜き出し、指標一覧の数値と照合**する。一覧にない数値が1つでもあれば、そのコメントを表示しない（再生成するか「生成できませんでした」と表示）
4. 「〜が原因」「〜のため増加」などの因果を断定する表現を検出し、警告する
5. AIが使えない場合：数値とグラフは表示し、コメント欄に「AIコメントは利用できません（理由）」とだけ表示する。固定応答をAIの分析として表示しない

指示書の Phase A〜D は、既存の Phase 2〜4 の機能（AI・画面・保存・Excel出力）に依存するため、次の順に組み込むことを提案する。

| 順 | 内容 | 依存 |

| 2 | **用語の統一**（用語集の作成と既存画面への適用） | — |
| 3 | **分析 Phase A**：分析エンジン（6種の分析ステップ＋スキーマ1.1＋単体テスト） | Phase 1 |

## 5. テスト方針

- 数値計算：中央値・標準偏差・前月比・前年比・増減率・構成比・ランキング（同順位）・期間別集計・ゼロ除算・欠損・丸めを、手計算した小さな表で検証（指示書10.1）
- 比較期間のデータがない場合に、数値が補完されないこと
- 作業手順 1.0 のファイルが 1.1 として読み込めること、保存→読込→同じデータで再実行→結果の指紋が一致すること
- AIコメント：一覧にない数値の混入を確実に拒否すること（固定の応答で再現テスト）
- 回帰：既存の全テストを毎回実行
