## 0. 本書の位置づけと前提

| 項目 | 内容 |
|---|---|
| 目的 | 実装前に構成・データ構造・検証方式を確定し、AI・UI・処理エンジンの共通言語を作る |
| 対象端末 | ワークスペース（業務操作）は**PCブラウザのみ**（Chrome / Edge 最新版、画面幅1280px以上推奨）。TOP画面のみスマートフォン・タブレットでも閲覧できるレスポンシブ対応（v1.1で変更） |
| 開発環境 | Windows 10 / VS Code / Python 3.12（3.15はpandas等の対応待ちのため使わない）/ Node.js 24 |
| 実行形態 | ローカル起動（開発・本人利用）と Docker（Hugging Face Spaces 公開）の2通り |

### 0.1 最重要設計原則

> 「AIで何でもできるように見せる」のではなく、「決められた業務を正確に、分かりやすく、何度でも実行できる」製品を作る。

これを設計判断に落とすと次の3ルールになる。

1. **AIは「提案者」であり「実行者」ではない。** AIが出すのはフローJSON（処理の設計図）だけ。実行はホワイトリスト化された処理ノードのみ。
2. **データは黙って変えない。** 削除・補完・型変換・キー正規化は、必ずノードとして明示され、ユーザーが確定したものだけ行う。
3. **疑わしい結果は成果物にしない。** 重大な不整合（エラー）があれば実行を「失敗」として扱い、処理結果シートを出力しない（検証レポートのみ出力可）。

### 1.1 責務分離のポイント

| 分離 | 理由 |
|---|---|
| AI（ai/）と処理（engine/）を分離 | AIが不調・未設定でも、保存済みフローの再実行は必ずできる（§8.5「AIを使わない再実行経路」） |
| フロー定義と入力データを分離 | フローJSONにはExcelの中身を入れない。再実行時は「入力の割当（バインディング）」だけ差し替える |
| フロントはフローの正本、サーバーはデータの正本 | サーバーはフローを保存しない（ステートレス）。毎回フロー全体を受け取って検証・実行する。状態同期のズレを最小化する |

## 3. データフロー（利用者の一連の操作）

```
①ファイル投入 → ②構造解析 → ③日本語で指示 → ④AIがフロー提案 → ⑤不足情報の確認
   → ⑥フロー確認・修正・確定 → ⑦実行 → ⑧品質検証 → ⑨Excel出力 → ⑩フローJSON保存

【翌月】保存JSONを読込 → 新ファイル投入 → 入力割当 → 互換性検証 → ⑦〜⑨（AI不使用）
```

画面上部にこの段階を「ステップ表示」として常に出し、現在地と次の操作を示す（§11）。

| ステップ | 表示名 | 完了条件 |
|---|---|---|
| 1 | データを読み込む | 必要な入力すべてにファイルが割り当て済み |
| 2 | 作業を伝える | AIがフローを返した（または手動でノード追加／JSON読込） |
| 3 | フローを確認する | 全ノードが「確定」 |
| 4 | 実行して検証する | 実行完了（エラー0件） |
| 5 | 出力・保存する | Excel出力 または フローJSON保存 |

## 4. 複数入力ファイルを扱うフローのデータ構造 【指定事項1・2】

### 4.1 考え方：「名前つきデータ置き場」方式

画面上は**上から下へ1列に並ぶ順序型**だが、内部では各ノードが「どのデータを使い、どのデータを作るか」を名前（データ参照名）で持つ。

```
[読込] 売上実績    → sales
[読込] 商品マスタ  → products
[結合] sales × products（商品コード）      → sales_p
[読込] 部署マスタ  → depts
[結合] sales_p × depts（部署コード）       → sales_full
[集計] sales_full を部署別に合計             → by_dept
[集計] sales_full を商品別に合計             → by_product
[出力] by_dept / by_product / sales_full をシートへ
```

- 画面の線（エッジ）は「参照関係」から自動で引く。結合ノードには2本の線が入る。
- ユーザーは自由に線をつながない（仕様9.6）。並び順と各ノードの設定で決まる。

### 4.2 依存関係のルール

| ルール | 検証内容 | 違反時 |
|---|---|---|
| R1 参照は「上にあるもの」だけ | 各ノードの入力参照は、自分より上のノードの出力でなければならない | 構造エラー |
| R2 出力名は一意 | 同じ参照名を2つのノードが作れない | 構造エラー |
| R3 循環禁止 | R1により順序型では原理的に循環しないが、JSON読込時に念のため検査 | 読込拒否 |
| R4 未使用の警告 | 誰にも使われず出力もされない参照 | 警告（実行は可） |
| R5 ノード移動 | 移動後にR1が崩れる場合は移動禁止し、「◯◯ノードの結果を使っているため、その下にしか移動できません」と表示 | 操作を拒否 |

`dependencies` フィールドは保存時に参照関係から**自動計算**して書き出す（人が手で書かない）。読込時は再計算値と一致するか検証する。

## 5. フローJSONスキーマ 【仕様10章】

詳細版は [flow-schema.md](flow-schema.md)（v1.2で作成）。Pydantic モデルを正本とする（フロントの型はそこから生成）。骨子は以下（※結合の左右の表し方など、一部は flow-schema.md の方式に変更済み）。

```jsonc
{
  "schema_version": "1.0",            // 未対応バージョンは明確なエラー
  "engine_version": "0.1.0",          // 保存時のエンジン版（再現性の確認用）
  "flow_id": "uuid",
  "flow_version": 3,                  // 保存のたびに+1
  "flow_name": "月次売上集計",
  "description": "…",
  "created_at": "2026-11-12T10:00:00+09:00",
  "updated_at": "…",

  "input_definitions": [              // 「どんなファイルが必要か」の定義（中身は持たない）
    {
      "input_id": "sales",
      "label": "売上実績",
      "file_kind": "xlsx",
      "sheet_hint": "売上",
      "header_row": 1,
      "columns": [
        { "name": "売上日",   "type": "date",    "required": true },
        { "name": "商品コード", "type": "string",  "required": true },
        { "name": "数量",     "type": "integer", "required": true },
        { "name": "金額",     "type": "decimal", "scale": 0, "required": true }
      ]
    }
  ],

  "nodes": [
    {
      "node_id": "n3",
      "node_type": "join",
      "node_name": "商品マスタと結合",
      "parameters": {
        "left": "sales", "right": "products",
        "keys": [{ "left": "商品コード", "right": "商品コード" }],
        "how": "left",
        "expected_relationship": "many_to_one",
        "unmatched_policy": "warn",          // warn | error
        "check_amount_columns": ["金額"]
      },
      "input_references": ["sales", "products"],
      "output_reference": "sales_p",
      "confirmation_status": "ai_proposed",  // unset | ai_proposed | pending | confirmed
      "open_questions": [                    // AIが確認したいこと
        { "param": "expected_relationship", "question": "商品マスタの商品コードは重複しない前提でよいですか？" }
      ]
    }
  ],

  "dependencies": [{ "node_id": "n3", "depends_on": ["n1", "n2"] }],   // 自動計算

  "validation_rules": {
    "max_row_growth_ratio": 1.0,       // 結合で行が増えてよい上限（既定：増加禁止）
    "amount_tolerance": "0",           // 金額比較の許容差（文字列＝Decimal）
    "stop_on_unmatched": false
  }
}
```

### 5.1 ノード状態

| 保存値 | 画面表示 | 色 | 意味 |
|---|---|---|---|
| unset | 未設定 | グレー #64748B | 必須パラメータが未入力 |
| ai_proposed | AI提案 | ブルー #2563A6 | AIが作った。人が未確認 |
| pending | 確認待ち | ブルー（点線枠） | AIからの質問に未回答 |
| confirmed | 確定 | グリーン #16845B | 人が確認済み |
| （実行結果）warning | 警告 | アンバー #B7791F | 実行時に警告あり |
| （実行結果）error | エラー | レッド #C24141 | 構造エラーまたは実行時エラー |

- 警告・エラーは**保存しない実行時の状態**（保存データと実行データの分離）。
- ノードの設定を手で変更すると状態は自動で「確定」になる（ユーザーが自分で決めたため）。AI提案のまま確定する場合は「この内容で確定」ボタンを押す。
- **1つでも unset / ai_proposed / pending があると実行ボタンは押せない**。理由をボタン横に表示する。

### 5.2 入力の割当（バインディング）＝実行データ

フローとは別物として扱い、**フローJSONには保存しない**。

```jsonc
{
  "bindings": [
    { "input_id": "sales", "file_id": "f_ab12", "sheet": "売上",
      "column_mapping": { "売上金額": "金額" } }   // 新ファイルで列名が変わったとき用
  ]
}
```

## 6. 処理ノード仕様（12カテゴリ） 【仕様6章】

| # | カテゴリ | node_type | 主なパラメータ | 検証・記録すること |
|---|---|---|---|---|
| 1 | ファイル読込 | `load` | input_id | 行数・列数・型変換失敗件数 |
| 2 | 行の抽出 | `filter` | 条件ツリー（AND/OR、11種の演算子） | 抽出前後件数 |
| 3 | 並べ替え | `sort` | 列・昇降順（複数） | 安定ソート（同順位は元の順序を保つ） |
| 4 | 列編集 | `rename_columns` / `drop_columns` / `add_constant` | 対応表・列名・固定値 | 追加列・削除列 |
| 5 | 型変換 | `cast` | 列ごとの型、日付書式、失敗時の扱い（error/warn） | 失敗件数・失敗した値の例 |
| 6 | 重複処理 | `duplicates` | キー列、mode（detect/remove）、残す行（first/last） | 重複件数・重複キー一覧 |
| 7 | 欠損値処理 | `missing` | 列、mode（detect/fill/drop_rows）、補完値 | 欠損件数、補完・除外した件数 |
| 8 | データ結合 | `join` | §7 参照 | §7 参照 |
| 9 | データ連結 | `concat` | 入力参照（複数）、列対応表、不足列の扱い | 各入力件数・合計件数・不足列 |
| 10 | グループ別集計 | `aggregate` | キー列、集計（sum/mean/max/min/count/nunique） | 集計前合計＝集計後合計（sum時） |
| 11 | 計算 | `calculate` | 新列名、式ツリー、丸め | ゼロ除算件数 |
| 12 | Excel出力 | `output` | シート名と参照の対応 | 出力行数 |

### 6.1 重要な設計判断

- **6.4「計算列追加」と6.11「計算」は1つの `calculate` ノードに統合**（同じ機能が2つあると利用者が迷うため）。
- **「検出」モードはデータを変えない。** 重複検出・欠損検出は件数と一覧を検証結果に出すだけ。
- **計算式は eval を使わない。** 式は次のような**JSONの木構造**で表し、許可された演算子（加減乗除・比率）と列参照・定数だけを解釈する専用関数で計算する。深さ上限5。

  ```json
  { "op": "subtract",
    "left":  { "op": "add", "left": {"col": "期首在庫"}, "right": {"col": "入庫数"} },
    "right": { "col": "出庫数" } }
  ```

- **ゼロ除算** は結果を空欄にし、件数と該当行を警告として出す（既定）。設定で「エラーで停止」に変更可能。
- **NULLキーは結合で一致させない。** pandasは既定で欠損同士を一致させてしまうため、結合前にNULLキー行を分離し、未照合として報告する。

## 7. データ結合時の整合性検証方式 【指定事項4・仕様7章】

結合ノードは次の順で検証し、**1つでもエラーなら後続ノードを実行しない**。

```
① 事前検査   キーの存在・型の一致・NULLキー件数
② 関係判定   左右それぞれのキー重複を数え、実際の関係を判定
③ 期待との照合 expected_relationship と比較
④ 件数予測   結合前に「結合後の行数」を計算で予測
⑤ 結合実行
⑥ 事後検査   実際の行数＝予測行数、金額合計の比較、未照合レコード抽出
```

### 7.1 関係判定

| 左キー重複 | 右キー重複 | 実際の関係 |
|---|---|---|
| なし | なし | 1対1 |
| なし | あり | 1対多 |
| あり | なし | 多対1 |
| あり | あり | 多対多 |

- 期待と実際が違う場合：**エラー（停止）**。例：「商品マスタに商品コードの重複が3件あります（A-001が2件…）。多対1の想定と異なります」＋重複キー一覧。
- 多対多は、ユーザーが明示的に「多対多を許可」した場合のみ実行可能。

### 7.2 行数増加の検証

- 予測行数 = Σ（キーごとの左件数 × 右件数）＋ 結合方式に応じた未照合行。
- 結合後の行数が `max_row_growth_ratio`（既定1.0＝増加不可。left結合・多対1なら左と同数のはず）を超えたら**エラー**。
- 表示例：「結合前 1,000件 → 結合後 1,250件（+250件）。原因：商品マスタのキー重複（A-001 ×2 ほか）」

### 7.3 金額整合性（処理内容で検証ルールを切り替える）

| ノード／条件 | 検証ルール |
|---|---|
| join（1対1・多対1、left/outer） | 左側の金額列合計：結合前＝結合後（一致しなければエラー） |
| join（inner） | 結合後合計＝「照合できた行」の結合前合計。差額＝未照合分として表示 |
| join（1対多・多対多） | 一致判定をしない（増えるのが正常）。増加額を情報として表示 |
| aggregate（sum） | 集計前の全体合計＝集計後の合計列の総和（NULLキー行の扱いも明示） |
| filter / missing(drop_rows) | 一致判定しない。除外された件数と金額を表示 |
| concat | 連結後合計＝各入力の合計の和 |

### 7.4 未照合レコード

- 件数・未照合キー・対象レコード（先頭100件＋Excelには全件）・**原因候補**を表示。
- 原因候補は「正規化すれば一致するか」で推定する（実データは変えない）：
  - 前後の空白（`"A-001 "`）／全角・半角（`Ａ-001`）／先頭ゼロ（`0123` と `123`）／大文字小文字
  - 例：「未照合12件のうち10件は、前後の空白を除くと一致します。『キーの空白を除去する』設定を有効にしますか？」
- 未照合の扱い（`unmatched_policy`）：既定は「警告して続行・未照合一覧を出力」。**自動削除はしない**（inner結合を選んだ場合も除外件数を必ず表示）。

### 7.5 重大エラー時の画面

エラーノードを赤枠で強調 → 右パネルに「何が起きたか／原因／直し方」の3点を表示 → 「処理結果」シートは出力しない（検証レポートのみ出力可・ファイル名に `_失敗` を付ける）。

## 8. 金額・小数・日付の扱い 【指定事項5】

| 型 | 内部表現 | 方針 |
|---|---|---|
| string | pandas `string` | **コード類は文字列のまま読む**（`00123` の先頭ゼロを失わない）。CSVは全列を文字列として読み、型は明示的に変換 |
| integer | pandas `Int64`（欠損可能な整数） | 小数部がある値は変換失敗として数える（黙って切り捨てない） |
| decimal | Python `Decimal`（列ごとに小数桁 `scale`） | **金額は浮動小数点にしない。** 合計・平均・比率はDecimalで計算し、指定桁で丸める |
| float | 使用しない（MVPでは decimal に統一） | 誤差の説明が難しいため |
| date | pandas `datetime64`（日付のみ・タイムゾーンなし） | Excelの日付セルはそのまま、文字列は書式指定（既定 `YYYY/MM/DD`・`YYYY-MM-DD`）で変換。失敗は件数表示 |
| boolean | pandas `boolean` | 許可値：TRUE/FALSE、1/0、はい/いいえ。それ以外は失敗扱い |

- **丸め方式はノードごとに選択**（`rounding` パラメータ：`half_up` 四捨五入／`down` 切り捨て／`up` 切り上げ／`half_even` 銀行丸め）。未指定時は四捨五入。選んだ方式は処理履歴シートに記録する（§14 Q2で確定）。
- 丸めを伴うノード：`cast`（decimal変換時）、`calculate`、`aggregate`（平均・合計）。
- 丸めは「計算の最後に1回」。途中で丸めて誤差を積み上げない。
- 平均は「合計（Decimal）÷件数」で計算し、欠損値は分母に含めない（件数と別に「欠損◯件を除外」と表示）。
- 性能：10万行のDecimal列の合計は1秒未満の見込み（Phase 1で実測し、結果を記録する）。

## 9. フロー保存・再実行の実装方式 【指定事項3・仕様11章】

### 9.1 保存方式

| 方式 | 対象 | 内容 |
|---|---|---|
| **JSONダウンロード／アップロード（必須）** | ローカル・公開環境の両方 | 「フローを保存」で `月次売上集計_v3.flowcraft.json` をダウンロード。翌月はこのファイルを読み込む |
| サーバー保存 | 将来拡張 | MVPでは実装しない（公開環境はファイルが永続しないため） |

- 保存時：`flow_version` を+1、`updated_at` 更新、`dependencies` 再計算、入力スキーマ（列名・型・必須）を最新に。
- 未保存の変更がある状態で画面を離れようとすると確認ダイアログを出す。

### 9.2 読込時の検証（失敗したら読み込まない）

JSON構文 → `schema_version` 対応確認 → Pydanticスキーマ検証 → ノード種類がホワイトリストにあるか → 参照整合性（§4.2） → `dependencies` 一致確認。エラーは「何行目のどの項目が何故だめか」を日本語で表示。

### 9.3 再実行と互換性検証

新ファイル割当後、実行前に次を自動検査し、結果を一覧表示する。

| 検査 | 判定 | 対応の案内 |
|---|---|---|
| 必須列がない | エラー | 似た列名を候補表示（例：「金額」→「売上金額」？）。対応付けを選ぶと `column_mapping` に記録 |
| 型が違う（変換失敗が出る） | 警告／エラー | 失敗件数と値の例を表示 |
| 日付書式が違う | 警告 | 書式候補を表示 |
| 結合キー・集計対象列がない | エラー | 上記と同じ対応付け |
| 余分な列がある | 情報 | 処理に影響しない旨を表示 |

### 9.4 再現性の保証

- 同一入力・同一フロー・同一エンジン版で同じ結果になるよう、乱数を使わない／ソートは安定ソート／集計キーは並び順を固定／結合は左の順序を保持。
- 実行ごとに**出力の指紋（SHA-256ハッシュ）**を計算し、処理履歴に記録。テストではこの値の一致で同一性を確認する。

## 10. 公開環境でのファイル管理・セキュリティ 【指定事項6・仕様16章】

### 10.1 セッションとファイル

- 初回アクセス時にサーバーがセッションID（推測困難な乱数）を発行。ブラウザのタブ単位で保持し、全APIに付ける。
- 他セッションのファイルIDは参照不可（ユーザー間のデータ混在防止）。
- アップロード原本は**解析後すぐ削除**し、解析済みデータのみメモリに保持。
- **最終操作から60分で自動削除**（設定変更可）。サーバー再起動でも消える。ディスクへの永続保存はしない。
- TOP画面・アップロード画面に「データの取り扱い」を明記（公開デモ環境には機密データを入れないよう注意喚起）。

### 10.2 ファイル検証

| 検査 | 内容 |
|---|---|
| 内容による形式判定 | xlsx：ZIP署名＋`[Content_Types].xml`・`xl/workbook.xml` の存在。CSV：NUL文字を含まない／文字コード判定可 |
| パスワード付き・旧形式 | OLE形式（暗号化xlsxや.xls）を検出して明確に拒否 |
| ZIP爆弾対策 | 展開後サイズの上限チェック |
| 制限 | 5ファイル・1ファイル10MB・合計10万行（`config.py`で変更可）。**結合後などの中間データにも上限50万行**を設け、超えたら停止 |
| ファイル名 | 表示用にのみ使い、保存パスには使わない（パストラバーサル対策） |
| 処理時間 | 1回の実行に上限（既定60秒） |

### 10.3 実行エンジンの禁止事項

eval / exec / 任意Python・シェル・SQL の実行は一切しない。ノードは `registry.py` のホワイトリストのみ、パラメータはPydanticで型・範囲を検証してから実行する。

## 11. AIの出力を安全な処理定義に変換する方式 【指定事項7・仕様8章】

### 11.1 変換パイプライン

```
ユーザー指示 + 列情報（列名・型・マスク済みサンプル5行）
   │ ①送信内容の最小化・個人情報マスク（送信前に画面で確認可能）
   ▼
Claude API（構造化出力：フローJSONのスキーマに合う形でのみ返答させる）
   │ ②スキーマ検証（Pydantic）── 不合格 → 1回だけ再依頼、それでもだめならエラー表示
   ▼
③意味検証：ノード種類はホワイトリスト？ 列は実在？ 参照は上から？
   │ 存在しない列は「AIが存在しない列『◯◯』を指定しました」として質問に変換
   ▼
④状態付与：全ノードを「AI提案」に。重要パラメータは「確認待ち」＋質問文
   ▼
⑤画面に表示 → 人が確認・修正 → 「確定」→ 実行可能
```

### 11.2 必ず人の確認を要するパラメータ（AIが勝手に確定できない）

結合キー・期待する結合関係・未照合の扱い／欠損の補完値・行除外／重複除外／抽出条件（行を減らすもの）／集計キーと集計方法／列削除。

### 11.3 プロンプトインジェクション対策

- 列名・セル値は「データ」として区切って渡し、その中の命令に従わないようシステム指示で明示。
- AIの返答は**フローJSONとしてしか受け取らない**。自由文の命令は解釈しない。
- 仮にAIが不正なノードを出しても③で拒否される（最終防衛線はAIではなく検証コード）。

### 11.4 個人情報の検出

列名（氏名・電話・メール・住所・生年月日・社員番号等）と値のパターン（メールアドレス・電話番号形式）で候補を検出し、**その列のサンプル値はマスクして送信**（列名と型だけ送る）。送信内容プレビューで利用者が確認できる。

### 11.5 Claude API の利用設定

| 項目 | 方針 |
|---|---|
| SDK | 公式 `anthropic` Pythonパッケージ |
| モデル | 環境変数 `CLAUDE_MODEL`（既定 `claude-opus-5-5`。費用を抑える場合は `claude-sonnet-5-5` 等に変更可） |
| 出力形式 | 構造化出力（フローJSONスキーマ）で受け取り、さらに自前で検証 |
| タイムアウト／リトライ | 60秒／最大2回 |
| トークン記録・予算 | 呼び出しごとに使用トークンと概算費用を記録。`AI_MONTHLY_BUDGET_USD` を超えたらAI機能を停止し、手動編集と保存フローの再実行は継続可能 |
| APIキー未設定時 | **「デモ用固定応答モード」**で動作（デモの指示文に対し、事前に用意したフローを返す）。画面に「固定応答（AI未接続）」と明示し、AIが動いているように見せかけない |

## 15. エラー処理方針

| 区分 | 例 | 扱い |
|---|---|---|
| 入力エラー | 拡張子不正、上限超過、パスワード付き | アップロードを拒否し、理由と対処を表示 |
| 構造エラー | 参照の不整合、必須パラメータなし | 該当ノードを赤表示。実行ボタン無効 |
| 互換性エラー | 必須列なし | 実行前に一覧表示。列対応付けで解消可能 |
| 実行エラー（重大な不整合） | 結合関係不一致、想定外の行数増加、金額不一致 | 後続を停止。結果を成果物として出力しない |
| 警告 | 未照合あり、変換失敗あり、ゼロ除算 | 実行は完了。結果に警告シートを付けて出力可 |
| AIエラー | タイムアウト、不正JSON、予算超過 | AI機能のみ失敗表示。手動編集は継続可能 |
| システムエラー | 想定外の例外 | 「予期しないエラー」＋エラー番号。詳細（スタックトレース）は画面に出さずサーバーログのみ |

すべてのエラーは `{ code, message(日本語), cause, how_to_fix, node_id? }` の共通形式で返す。

| 単体 | pytest | 12カテゴリの各ノード、型変換、Decimal丸め、計算式評価 | 全件成功 |
| 境界値 | pytest | 空ファイル、ヘッダーのみ、1行、重複列名、全件欠損、型不一致、ゼロ除算、最大サイズ・最大行数 | 期待どおりのエラー／警告 |
| 結合・集計 | pytest | 1対1／1対多／多対1／多対多、NULLキー、重複キー、行数増加、金額不一致。**期待値は手計算した小さな表で固定** | 全件成功 |
| 保存・再実行 | pytest | 作成→保存→（新しいプロセスで）読込→同一データ再実行→ハッシュ一致→新データ再実行→列変更時の互換性エラー | 全件成功 |
| AI | pytest＋固定応答 | 正常・曖昧・存在しない列・未対応処理・不正JSON・必須不足・APIエラー・タイムアウト | 不正な出力が実行に到達しない |
| API | pytest＋TestClient | 各エンドポイントの正常・異常、セッション分離 | 全件成功 |
| E2E | Playwright（Chromium） | TOP→デモ→生成→編集→実行→結果→Excel→保存→再読込→再実行 | デモA・Bが最後まで通る |
| 手動受入 | チェックリスト | 自分のExcelでの一連操作、UIの分かりやすさ | §19 |

テスト結果は実行日・件数・失敗内容を `docs/test-report.md` に記録する（未実施のものを成功と書かない）。

## 21. 製品方針 Ver.3.0 による影響分析（2026-11-12）

### 21.1 変わらないもの（そのまま使う）

| AI（§11） | 作業手順の作成は Phase 5。列名変更の候補提示・エラーの説明を追加。重大度の判定にAIを使わない |
