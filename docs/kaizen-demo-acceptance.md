## 設計上の判断（説明できるようにしておく点）

- **AIは使っていない**：改善候補は決まった規則（`backend/app/kaizen/diagnose.py` の KD-1〜KD-4）で見つける。同じ入力なら同じ結果になり、理由を説明できる。AIは Phase 5 で、この上に「規則にない改善の候補」「説明の言い換え」として足す予定
- **廃止は提案にとどめる**：「要件はない」と利用者が確かめたときだけ採用できる。画面とサーバーの両方で確かめる
- **採用すると、実際の処理が変わる**：判断から、通常の作業手順と同じ形の作業手順を組み立てる（`backend/app/kaizen/build.py`）。説明の文章だけを変えるのではない
- **できないことは「未対応」と示す**：会議用資料の作成・送付は処理エンジンで行えないため、手作業として残し、その時間も数える
- **想定値と実測を分ける**：作業時間は架空の設定値から計算した想定値と明記する。工程数・処理ステップ数は作った手順から数えた事実。実行結果は実際の処理エンジンの結果
- **改善前の手順を壊さない**：改善後の作業手順は新しい作業手順（版1）として作る

- 作業時間は想定値。実際に測った時間を入力して効果を比べる機能は未実装
