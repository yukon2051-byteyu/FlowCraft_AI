# AI利用の認証と利用上限 設計書（ai-auth-design.md）

- 版：v0.1（2026-11-13 設計。AI 機能そのものが Phase 5 のため、実装は Phase 5 の最初のタスク）
- 元の指示：AI利用認証のタイミング・操作性改善指示書（2026-11-13）
- 基本方針：**AI を実際に呼び出す直前に認証し、認証に成功したら、利用者が最初に選んだ AI の操作を自動で続ける**

---

## 1. 今の状況（2026-11-13 調査）

| 項目 | 状況 |
|---|---|
| AI を呼び出す機能 | **まだない**（Phase 5）。画面の AI のボタン（「AIで作業手順を作る」「この作業を見直す」など）は「開発中」で押せない |
| パスワードを求める画面 | **ない**。TOP の「自分のExcelで試す」・デモの開始・読み込み・実行・Excel 出力で、パスワードは求めない |
| 設定 | `backend/app/config.py` に AI の上限（`ai_monthly_budget_usd` など）の項目だけがある |

→ 指示書の「AI を使わない限りパスワードは不要」は、今の時点で満たしている。**E2E で、パスワードを求めないことを確かめるテストを追加した**（`e2e/no-ai-auth.spec.ts`）。AI 機能を作るときに、この設計で認証を加える。

## 2. 認証が要る操作・要らない操作

| 認証が要る（外部の有料 AI を呼ぶ） | 認証が要らない |
|---|---|
| AI業務改善診断・改善提案 | Excel・CSV の読み込み、プレビュー、列・行数・形式の確認 |
| AI による作業手順の作成 | 空白・欠損の検出（Phase Q の規則による判定） |
| AI による完了基準の提案 | 手動での作業手順・完了基準の設定 |
| AI による分析コメント・異常の原因の推定 | 実行（AI を使わない処理）、品質検証、総合判定、Excel 出力 |
| | 保存・読み込み・再実行、デモ（AI を使う部分を除く） |
| | 無人実行（AI を使わない作業手順） |

## 3. 認証状態の管理（サーバー側）

```text
POST   /api/ai/auth     { password }  → 成功：このセッションに「AI を使ってよい」印（期限つき）をサーバーで付ける
GET    /api/ai/auth                   → 認証の状態・残りの期限・今日の残りの利用枠
DELETE /api/ai/auth                   → 解除（共有PCで「AIの利用を終える」）
```

- パスワードは環境変数（Hugging Face の Secrets）に**ハッシュ**で置き、サーバーで比べる（比べる時間で推測されない方法）。ブラウザ・localStorage・ログには残さない
- 認証の印は**サーバーのセッション**に付ける（ブラウザはセッション番号だけを持つ。今の仕組みと同じく、タブを閉じれば消え、再読み込みでは消えない）
- 期限：最後に AI を使ってから60分、最長8時間。過ぎたら再認証
- 失敗の制限：同じセッション・同じ接続元で15分に5回まで。超えたらしばらく受け付けない（理由を表示）

## 4. 利用回数・費用の上限（すべての AI の API で、呼び出す前に確かめる）

| 管理すること | 方法 |
|---|---|
| 呼び出しの記録 | 機能・日時・入力と出力のトークン数・推定費用を、セッションごとと全体で記録（パスワード・APIキー・業務データは記録しない） |
| 上限 | 全体の月の予算（`ai_monthly_budget_usd`）、セッションごとの1時間あたりの回数・トークン数 |
| 同時実行で上限を超えない | 呼び出す前に、その呼び出しの最大の費用を**先に確保**（ロックの中で）し、終わったら実際の費用に直す |
| 上限を超えたら | AI を呼ばずに「今月のAIの利用上限に達しました」などを返す（AI を使わない機能はそのまま使える） |

- 実装は、すべての AI の API に共通の「確認の部品」（FastAPI の依存関係 `require_ai(feature)`）として作り、付け忘れを防ぐ。画面のボタンを隠すだけの制御はしない
- API キーはサーバーだけが持つ（画面に渡さない）

## 5. 認証後の自動復帰（画面）

```text
利用者が「AIで作業手順を作る」を押す
  → 画面は AI の API を呼ぶ（認証済みか分からなくても、まず呼ぶ）
  → サーバーが「認証が必要」（401 AI_AUTH_REQUIRED）を返す
  → 画面は「やろうとした操作」を覚えたまま、認証のダイアログを開く（画面の入力・読み込んだファイルはそのまま）
  → パスワード入力 → POST /api/ai/auth → 成功
  → ダイアログを閉じ、覚えておいた操作を自動でもう一度呼ぶ（利用者はボタンを押し直さない）
失敗：ダイアログに「パスワードが正しくありません。」。AI は呼ばない
キャンセル：ダイアログを閉じるだけ。覚えておいた操作は捨て、画面の入力はそのまま
```

- 画面の共通の部品 `useAiAction(機能, 実行する関数)` として作り、すべての AI のボタンで使う（ボタンごとに作らない）
- ダイアログ：題「AI機能を利用する」、説明「この機能ではAIを使用します。利用するにはAIパスワードを入力してください。」、入力欄「AI利用パスワード」（表示・非表示の切り替え）、「認証して続ける」「キャンセル」。入力欄に自動で合わせる、Enter で送る、送信中は二重に送らない
- 一度認証すれば、同じセッションの間はほかの AI 機能でも聞かない

## 6. デモ・無人実行

- デモ：開始時には聞かない。AI の改善提案などを使うときだけ、上の流れで聞く
- 無人実行（クラウドの3分後・Windows Worker）：**MVP では AI を使わない作業手順だけを実行する**。ブラウザの認証は使わない（流用しない）
  将来 AI を使う場合は、案件ごとに「AI を使ってよい」権限と上限をサーバーで設定し、Worker 専用の資格情報で呼ぶ。権限・上限の設定がない案件は有効化できないようにする（5段階の確認の中で確かめる）
