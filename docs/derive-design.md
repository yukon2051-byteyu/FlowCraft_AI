## 2. 方針

- **元の手順は読み取り専用**：複製時に新しい `flow_id` を発行し、元のJSONは一切書き換えない（複製はデータの深いコピー）
- **AIは変更案（構造化JSON）だけを返す**：変更案は「どのステップの・どの設定を・何から何へ・なぜ・確認が必要か・影響」を持つ。採用された変更だけを手順に反映し、反映後の手順を既存の検証に通す
- **列対応は自動で確定しない**：列名・型・サンプル統計・処理上の役割（結合キー・集計対象など）から候補と信頼度を出すが、すべて「確認待ち」として利用者が選ぶ
- **AIなしでも使える**：複製と手動での変更は、AIが使えなくてもできる
- **数値が違うことはエラーにしない**：変更前後で件数・金額を並べて表示し、想定外の変化（行数の急増・除外件数の急変など）を警告する

## 3. 作業手順JSONへの追加（スキーマ 1.1、分析機能の変更と同時に行う）

```jsonc
"derived_from": {               // もとにした手順（新規作成なら null）
  "flow_id": "…", "flow_version": 3, "flow_name": "営業部A 月次売上集計"
},
"change_log": [                 // 採用した変更の記録
  { "at": "2026-11-12T10:00:00+09:00", "step_id": "n7", "kind": "parameter_changed",
    "summary": "部署ごと → 担当者ごとに合計", "reason": "…", "source": "ai" | "user" }
]
```

1.0 の手順は `derived_from: null`・`change_log: []` として読み込む（移行処理）。
