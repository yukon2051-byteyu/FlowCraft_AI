# FlowCraft AI 実装計画（implementation-plan.md）

- 版：**v2.0（2026-11-12）**：製品方針 再定義・開発計画改訂指示書 Ver.3.0 にもとづき全面改訂
- 前提：[product-review.md](product-review.md)（製品方針と設計判断）／[architecture.md](architecture.md)
- 進め方：**1タスクずつ実装 → テスト → 説明 → 確認をもらってから次へ**
- ルール：各Phaseの最後に「完了チェック」を行い、重大な問題が残っていれば次へ進まない

凡例：☐ 未着手 / ◐ 作業中 / ☑ 完了（テスト済み）

## 判断基準（Ver.3.0 §17）

すべての設計判断は、次の問いで評価する。AI機能の数や画面の華やかさでは判断しない。

1. 毎月同じ業務を安定して実行できるか
2. 入力データの変化に気づけるか
3. 誤集計のリスクを検出できるか
4. 問題が起きた理由を利用者に説明できるか
5. 担当者が変わっても業務を継続できるか
6. 作成した作業手順を安全に管理できるか

## 最初の到達目標「M1：価値を示す3つのデモ」

AI機能がまだ限定的でも製品価値を説明できるよう、次の3つを**実際に動くデモ**として最初に完成させる（Phase 1・Phase 2・Phase 3の一部）。

| # | デモで見せること | 必要なタスク |
|---|---|---|
| 1 | 先月の作業手順を、今月のExcelで再実行する | 1-0〜1-10 |
| 2 | 列名の変更・データの欠落などを検出し、利用者に分かりやすく知らせる | 2-1〜2-3 |
| 3 | 検証結果を確認し、問題がなければレポートを出力する（問題があれば確定結果を出さない） | M1-1・M1-2（3-7・3-8 の最小版を前倒し） |

**M1 の完了条件**：架空の「先月分」「今月分（列名の変更・必須項目の欠落・マスタにない商品コード入り）」で、上の3つを最初から最後まで操作できること（E2E）。

| # | タスク（前倒し分） | 完了条件 |
|---|---|---|
| M1-1 | 総合判定（正常／注意／重大）の最小版：既存の検証（列構成・結合・集計・空欄）を判定に集約。注意は確認してから出力、重大は確定結果を出さず検証結果のみ出力 | §14「異常時の制御」のうち、既存の検証で起きるケース |
| M1-2 | 1枚レポートの最小版（画面・Excel）：総合判定・入力ファイル・件数・照合・金額・注意事項 | 実際のExcelで開いて確認 |

前回との比較・対象期間・正解値・業務ルールは、M1 の後に Phase 3 で追加し、判定とレポートに組み込む。

**画面の構成（Phase 1 から前提にする）**：作る画面 `/build`、回す画面 `/run`（Phase 4）。現在の `/workspace` は `/build` に移す（旧URLは転送）。処理ステップは**縦の一覧**で表示し、React Flow は使わない（product-review.md §9）。

## Phase 1：作業手順の作成・保存・読み込み・再実行・Excel出力（最優先）

**目的**：AIを使わずに、Ver.3.0 §3 の10の操作（読み込む→作る→テスト実行→検証結果を見る→保存→読み込む→新しいファイルを指定→互換性を確認→再実行→結果と検証を出力）を完結させる。互換性の確認（操作8）は、Phase 1 では「必須列が足りなければ実行前に止める」までとし、詳しい比較と対応付けは Phase 2 で作る。

| # | タスク | 完了条件 |
|---|---|---|
| 1-0 | **デモ用の架空データ**：先月分・今月分の売上（今月分は列名の変更・列順の変更・必須項目の空欄・マスタにない商品コードを含む）、商品・部署マスタ。シード固定で生成し、全Phaseの受入テストに使う | 仕込んだ問題が毎回同じ件数で現れる |
| 1-1 | 画面の土台：作業手順の状態管理（作業手順の内容・入力の割当・未保存の印）、URLを `/build` へ整理、画面側の単体テストの仕組み（Vitest） | 状態管理の単体テストが通る。`/workspace` から `/build` へ移動する |
| 1-2 | 新しく作る：読み込んだファイルから「入力の定義」（使う列とデータの形式）を作る画面。推定した形式を利用者が確認・変更する | 先頭0のコードを「文字」のまま定義できる。E2E |
| 1-3 | 処理ステップの一覧（縦）：追加・削除・上下移動。各ステップに「使うデータ」（例：ステップ2の結果・商品マスタ）を表示。つながりを壊す移動は理由を示して止める | 結合・枝分かれを含む手順が正しく表示される。禁止される移動のテスト |
| 1-4 | 処理内容の設定フォーム（よく使う9種）：読み込む・条件で残す・必要な列を取り出す・列の名前を変える・情報を付け加える・縦にまとめる・合計・集計する・計算する・Excelに出力する | 9種を画面から設定でき、設定がサーバーの検証を通る |
| 1-5 | 処理内容の設定フォーム（残り6種）：並べ替える・不要な列を消す・同じ値の列を追加する・データの形式をそろえる・重複・空欄 | 15種すべてを画面から設定できる |
| 1-6 | テスト実行：選んだステップの処理前後のデータ・件数・メッセージ（`/api/flows/preview`）、全体の実行（`/api/runs`）。旧1-15の画面接続 | ステップを選ぶと処理前後のデータが見える。E2E |
| 1-7 | Excel出力：処理結果のシート＋検証結果のシート＋処理の記録。実行がエラーなら処理結果のシートを出さない | 出力ファイルを読み戻して内容を確かめるテスト。**実際のExcelで開いて確認** |
| 1-8 | 保存：作業手順をファイル（.json）に保存、ブラウザ内の「保存した作業手順」一覧にも保存。保存のたびに版数を上げる。未保存のまま離れようとすると確認 | 保存したファイルが形の決まりの検証を通る |
| 1-9 | 読み込み：ファイルまたは一覧から開く → 検証 → 復元。新しいファイルを入力に割り当てる画面（必須列が足りなければ実行前に止めて理由を示す） | 処理ステップの構成・設定・順序が完全に復元される |
| 1-10 | **保存→読み込み→再実行の自動テスト**：同じデータなら結果の指紋が一致、新しいデータでも再実行できる、アプリを再起動しても読み込める | すべて成功 |
| ☐ | **Phase 1 完了チェック** | 10の操作がAIなしで最後まで通る（E2E）。全テスト成功。test-report.md に記録 |
